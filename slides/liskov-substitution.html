L — Subtypes Must Honor the Base Contract

"Any subtype should be usable wherever the base type is expected."

Where It Applies

User roles & authentication.

All three descend from User, so .login() and .updateProfile() behave identically no matter which subclass arrives.

Correct Substitution Guarantees

Three promises the base contract makes.

Both Passenger and TravelAgent are treated as a User wherever the system calls login() or updateProfile().

AuthController.authenticate(user) works identically no matter which specific subclass it receives.

Prevents the "Penguin can't fly" trap: no specific actor subtype breaks a generic system operation that the base type promises to fulfil.
