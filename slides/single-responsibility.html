Principle 01 · S

S — Each Class Does One Job

"A class should have only one reason to change."

Bad Design — Before

class ReservationManager { ... }

A single "God Class" handles every concern:

01Querying flights
02Calculating taxes
03Saving to the database
04Processing credit cards
05Generating the PDF boarding pass

Risk: Changing the payment gateway logic risks breaking the seat allocation code.

Airline Design — After

Four specialised services

→

class FlightSearchEngine { }

strictly queries available routes

→

class SeatAllocationService { }

only handles seat locking

→

class PaymentProcessor { }

exclusively manages financial transactions

→

class TicketGenerator { }

focuses solely on creating the final E-Ticket
